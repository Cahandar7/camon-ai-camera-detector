# CamOn — AI-мониторинг чистоты

Камеры следят за зонами любой территории — парка, музея, вокзала, торгового центра, кампуса. Нейросеть в реальном времени находит **мусор и людей**, считает **индекс чистоты** каждой зоны и сразу сообщает персоналу, где нужна уборка. Не нужно ждать обхода по графику.

- **Real-time видео** с полной частотой камеры (30 FPS), рамки AI рисуются поверх видео
- **Детекция:** человек, бутылка, стакан, банка, пакет, бумага
- **Индекс чистоты 0–100 %** для каждой зоны и среднее по всем зонам
- **Вход по учётным записям** (публичной регистрации нет, пользователей создаёт администратор), 4 языка интерфейса (AZ, EN, RU, TR)
- **Алерты:** зона загрязнена; мусор лежит дольше N секунд; зона снова чистая. К каждому алерту прикладывается снимок с разметкой
- **Защита от ложных срабатываний:** мусор засчитывается, только если пролежал ≥ 1 с; бутылку в руке человека система не считает мусором
- Работает на обычном ноутбуке **без видеокарты** (~40 мс на кадр на Intel i7)

## Быстрый старт

```bash
./setup.sh          # один раз: Python-окружение, модель YOLO, npm-пакеты
./start.sh prod     # демо-режим, всё на одном порту → http://localhost:8000
./start.sh          # режим разработки (hot reload) → http://localhost:5173
```

Требования: Linux/macOS, Python 3.12, Node 20+. Первый запуск скачивает модель и оптимизирует её под процессор (~1–2 мин).

## Вход и пользователи

Регистрации нет — учётные записи создаёт администратор. При первом запуске создаётся тестовый администратор **admin@gmail.com / 123456** (смените пароль перед реальным использованием). Пока нет панели администратора, пользователи управляются из терминала:

```bash
cd backend
.venv/bin/python -m app.auth add operator@example.com "пароль"      # роль user
.venv/bin/python -m app.auth add boss@example.com "пароль" --role admin
.venv/bin/python -m app.auth list
.venv/bin/python -m app.auth passwd admin@gmail.com "новый пароль"
.venv/bin/python -m app.auth delete operator@example.com
```

Пользователи и сессии хранятся в `backend/data/camon.db` (SQLite): id, email, роль, дата создания и изменения; пароль — только в виде хеша scrypt. Сессия — HttpOnly-cookie на 7 дней.

## Подключение телефона (IP Webcam)

1. Установите на Android приложение **IP Webcam** и нажмите **Start server**.
2. Телефон и компьютер должны быть в **одной Wi-Fi сети**.
3. В CamOn нажмите **Add camera** → **IP Webcam**, введите адрес с экрана телефона (например `192.168.1.25:8080`), затем **Test connection** → **Add camera**.

Рекомендуемые настройки в приложении (*Video preferences*): разрешение **1280×720**, качество **50–70**, FPS limit **30**. Чем выше разрешение и качество, тем сильнее нагрузка на Wi-Fi.

Другие источники (тот же диалог):

| Источник | Пример |
|---|---|
| CCTV / RTSP камера | `rtsp://user:pass@192.168.1.64:554/stream1` |
| IP Webcam через RTSP (H.264) | `rtsp://192.168.1.25:8080/h264_ulaw.sdp` |
| USB / встроенная веб-камера | `0` |
| Видеофайл (для демо, крутится по кругу) | `/home/user/demo.mp4` |

## Архитектура

```
 Телефон / CCTV ──MJPEG/RTSP──▶ ┌─────────────── Backend (FastAPI) ────────────────┐
                                │  reader-поток ──▶ последний кадр ──┬──▶ MJPEG ───┼──▶ <img>  видео 30 FPS
                                │  (без очереди)                     │             │
                                │                                    ▼             │
                                │                   AI-поток: YOLOE-26 + ByteTrack │
                                │                   → аналитика чистоты, алерты ───┼──▶ WebSocket ──▶ <canvas> рамки
                                └──────────────────────────────────────────────────┘          + панели, графики
```

**Почему видео не лагает.** Обычно тормоза возникают из-за того, что видео ждёт нейросеть: кадр → YOLO → рисуем рамки → кодируем → отправляем. Здесь эти процессы разделены:

1. **Видео идёт мимо AI.** JPEG-кадры с IP Webcam уходят в браузер как есть, без декодирования и перекодирования, поэтому FPS равен FPS камеры.
2. **AI всегда берёт самый свежий кадр.** Очереди нет, поэтому задержка не накапливается. Кадры, пришедшие, пока модель занята, AI пропускает, но в видео они попадают.
3. **Рамки рисует браузер** на canvas с частотой 60 FPS и плавно ведёт их к новой позиции (интерполяция по ID трека). Даже при 15 AI-FPS движение выглядит плавным.
4. **Модель оптимизирована под CPU:** OpenVINO + INT8-квантизация + инференс без масок, около 40 мс на кадр вместо ~110 мс на PyTorch.

## Модель

По умолчанию используется **YOLOE-26s** (Ultralytics, 2026). Это YOLO26 с открытым словарём: классы задаются текстом, без дообучения. Словарь мусора записан в [backend/app/detector.py](backend/app/detector.py) (`VOCABULARY`):

```python
VOCABULARY = {"person": "person", "bottle": "bottle", "cup": "cup",
              "soda can": "can", "plastic bag": "bag", "paper": "paper"}
```

Чтобы добавить новый тип мусора, достаточно одной строки (например `"cigarette pack": "paper"`). При следующем запуске модель пересоберётся автоматически.

Можно переключиться на классическую COCO-модель: `CAMON_MODEL=yolo26s` в `backend/.env` (см. `.env.example`).

> **YOLO не оценивает чистоту, она только находит объекты.** Процент чистоты считает слой аналитики ([backend/app/analytics.py](backend/app/analytics.py)): каждый подтверждённый предмет добавляет «вес» (бутылка 1.0, пакет 1.3, бумага 0.6 …), индекс = 100·e^(−Σвесов/6). Одна бутылка ≈ 85 %, три ≈ 61 %, шесть ≈ 38 %. Значение сглаживается, чтобы шкала не дёргалась.

Уровни: **Clean** ≥ 80 · **Light litter** ≥ 60 · **Dirty** ≥ 40 · **Critical** < 40. Порог алерта, время до алерта о мусоре и уверенность детекции меняются в настройках интерфейса.

## Структура

```
backend/
  app/main.py        REST API, MJPEG-стримы, WebSocket
  app/cameras.py     потоки чтения и инференса для каждой камеры
  app/sources.py     IP Webcam / MJPEG (pass-through), RTSP/файлы/веб-камеры (FFmpeg)
  app/detector.py    подготовка модели (YOLOE → INT8 OpenVINO), детекция + трекинг
  app/analytics.py   индекс чистоты, время лежания мусора, алерты
  data/              камеры, настройки, алерты и снимки (создаётся автоматически)
frontend/src/
  lib/overlay.js     отрисовка рамок на canvas с интерполяцией
  components/        LiveView, Gauge, Overview, модальные окна …
```

## API

| Метод | Путь | |
|---|---|---|
| GET | `/api/health` | модель, рантайм, устройство, классы |
| GET/POST | `/api/cameras` | список / добавить камеру |
| PUT/DELETE | `/api/cameras/{id}` | изменить / удалить |
| POST | `/api/cameras/test` | проверить URL, вернуть превью |
| GET | `/api/cameras/{id}/stream` | видео (MJPEG) |
| GET | `/api/cameras/{id}/snapshot?w=640` | текущий кадр |
| WS | `/api/ws/cameras/{id}` | детекции и статистика в реальном времени |
| WS | `/api/ws/events` | сводка по камерам и алерты |
| GET/PUT | `/api/settings` | пороги и уверенность |
| GET/DELETE | `/api/alerts` | история алертов |
